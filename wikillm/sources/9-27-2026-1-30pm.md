

# ชิ้นที่ 1: `knowledge.md` (วางไว้ที่ root ก่อนเริ่ม)

````markdown
# ProjectF — Project Knowledge

## What this is
A cozy pixel-art fishing/farming game (Stardew Valley visual style, Pixels.xyz structure)
built on **Libplanet** (C# blockchain library), with a separate real-time presence layer.

## Hard architectural rules — NEVER violate these

1. **Two-layer split is absolute.**
   - Consensus layer (Libplanet): anything affecting ownership or economy —
     inventory, gold, stamina, levels, fish roll results, craft results, pond slot ownership.
   - Presence layer (MagicOnion): cosmetic only — player position, facing, animation state, emotes.
   - NEVER put position/animation on-chain. NEVER let the presence layer decide ownership.

2. **All `IAction.Execute()` code MUST be 100% deterministic.**
   - FORBIDDEN inside Execute: `DateTime.Now`, `DateTime.UtcNow`, `System.Random`,
     `Guid.NewGuid()`, file I/O, network calls, `Environment.*`, unordered collection iteration.
   - Use `context.BlockIndex` instead of wall-clock time.
   - Use `context.GetRandom()` for ALL randomness.
   - Use `SortedDictionary`/ordered iteration when serializing, never `Dictionary` enumeration order.

3. **No cron/scheduler exists on a blockchain.**
   - Crop growth: store `PlantedAt` block index; evaluate `context.BlockIndex - PlantedAt >= GrowBlocks` at harvest.
   - Pond occupancy: store `ExpiresAtBlock`; lazily clean up expired slots when the next action touches that pond.
   - Stamina: store `StaminaUpdatedAt`; regenerate by elapsed block count on read.

4. **Target frameworks.**
   - `ProjectF.Lib`, `ProjectF.Shared`, `ProjectF.Tables` → `netstandard2.1` ONLY (Unity must load these DLLs).
   - `ProjectF.SeedNode`, `ProjectF.HubServer` → `net8.0`.
   - Unity cannot consume NuGet directly; DLLs are copied via `tools/sync-dlls.ps1`.

5. **Serialization boundaries.**
   - Unity ↔ Libplanet → **Bencodex** (mandated by Libplanet).
   - Unity ↔ MagicOnion → **MessagePack** (`[MessagePackObject]` + explicit `[Key(n)]`).
   - CSV → code → **Luban** (`cs-bin`), output shared by both server and Unity.
   - **Do NOT add Protobuf.** There is no cross-language boundary in this project.

6. **Signer validation.** Every action that mutates a player's state must verify
   `context.Signer == AvatarAddress` before doing anything else.

## Reference projects (patterns to follow)
- https://github.com/planetarium/planet-clicker — overall Unity + Libplanet wiring
- https://github.com/planetarium/lib9c — action/state structure at scale
- https://github.com/Cysharp/MagicOnion — StreamingHub patterns

## Tech stack (fixed — do not substitute)
Unity 2022.3 LTS (URP 2D) · VContainer (DI) · UniTask (async) · MessagePack ·
MagicOnion 7.x (presence) · Libplanet 5.x (chain) · Luban (CSV data tables) · xUnit (tests)

## Style conventions
- C# file-scoped namespaces, nullable enabled, `sealed` on concrete classes.
- Unity: MVP pattern — `XxxPresenter` (logic, plain C# + VContainer) / `XxxView` (MonoBehaviour, no logic).
- One `LifetimeScope` per scene, `RootLifetimeScope` for app-lifetime singletons.
- Presence sends at 10 Hz max, never per-frame; clients interpolate.
- Comments in code: English. Commit messages: English.
````

## 2. ProjectF.Lib — the on-chain core

States (all Bencodex-serializable, deterministic ordering):
- `AvatarState`   — Name, FishingLevel/Exp, CookingLevel/Exp, Stamina, MaxStamina,
                    StaminaUpdatedAt, Gold (start 300), KitchenUnlocked.
                    Methods: `SyncStamina(blockIndex, regenPerBlock = 1)`, `SpendStamina(cost)`,
                    `AddFishingExp(exp)`, `AddCookingExp(exp)` (level up from TbLevelExp).
- `Inventory`     — flat `SortedDictionary<int itemId, int count>`;
                    `GetCount`, `Add`, `TryRemove`, `RemoveOrThrow`, `All`, `Clone`, `DiffAgainst`.
- `FarmPlotState` — PlotIndex, SeedId, PlantedAt, `IsEmpty`, `Plant`, `Clear`.
- `PondOwnershipState` — PondId + `SortedDictionary<Address, long expiresAtBlock>`;
                    `HasActiveSlot`, `ActiveCount`, `Occupy`, `Renew`, `Release`, `ReleaseExpired`.
- `TaskBoardState` — per-avatar daily task ids + completion flags, rerolled per N blocks.

`Addresses` static class: separate account spaces (Avatar, Inventory, Farm, Pond, TaskBoard),
plus deterministic key derivation `PondKey(int)` and `PlotKey(Address, int)`.

`ActionBase : IAction` with shared helpers: `GetAvatar`, `GetInventory`, `Save`,
`EnsureOwner(ctx, avatarAddress)`. Use a `type_id` + `values` PlainValue envelope.

Actions to implement fully:
| ActionType id         | Behaviour |
|-----------------------|-----------|
| `create_avatar_v1`    | create AvatarState + starter inventory (wooden rod x1, worm x5, 300 gold) |
| `occupy_pond_v1`      | lazy-release expired slots, renew if already held, else claim if `ActiveCount < SlotCount`, else throw `PondFullException` |
| `leave_pond_v1`       | voluntary release |
| `fishing_v1`          | require active pond slot; validate rod owned + bait consumed; `SyncStamina` then spend `max(1, 5 - rod.StaminaDiscount)`; hit chance = `min(95, pond.BaseHitRate + rod.HitBonus + bait.HitBonus + level*2)`; on miss grant 1 exp; on hit do a weighted fish roll (rare weight boosted by bait.RareBonus + rod.RareBonus when `fish.Rarity >= 3`), roll size, grant item + exp |
| `craft_food_v1`       | require `KitchenUnlocked`; Portions 1..10; validate cooking level; spend `recipe.StaminaCost * Portions`; remove ALL materials atomically; per portion roll `min(40, 5 + cookingLevel*2)`% for the "great" variant |
| `eat_food_v1`         | consume 1 food, restore stamina capped at MaxStamina |
| `plant_seed_v1`       | consume seed + stamina, write `PlantedAt` |
| `harvest_v1`          | require `BlockIndex - PlantedAt >= GrowBlocks`, roll yield, clear plot |
| `buy_item_v1`         | fixed-price NPC shop, deduct gold, respect RequiredLevel |
| `submit_task_v1`      | verify + consume required items, pay gold/exp/bonus item, mark completed |

Custom exceptions in `Exceptions/`: `NotEnoughStaminaException`, `ItemNotFoundException`,
`PondFullException`, `NotEnoughGoldException`, `FailedLoadStateException`.

Also: `Policy/BlockPolicySource.cs` (2s target block interval, max tx per block, max tx bytes)
and `Genesis/GenesisHelper.cs` (build + persist a genesis block).

## 4. ProjectF.Shared — presence contracts

MessagePack models: `PlayerJoinRequest`, `PlayerMoveRequest` (struct), `PlayerSnapshot`,
`PondHintMessage`; enums `Direction : byte`, `AnimationState : byte {Idle,Walk,Fishing,Watering,Cooking}`.

```csharp
public interface IPlayerHubReceiver {
    void OnSceneSnapshot(PlayerSnapshot[] players);
    void OnJoin(PlayerSnapshot player);
    void OnLeave(string sessionId);
    void OnMove(PlayerSnapshot player);
    void OnEmote(string sessionId, int emoteId);
    void OnPondHint(PondHintMessage hint);
}
public interface IPlayerHub : IStreamingHub<IPlayerHub, IPlayerHubReceiver> {
    ValueTask<PlayerSnapshot[]> JoinAsync(PlayerJoinRequest request);
    ValueTask MoveAsync(PlayerMoveRequest request);
    ValueTask EmoteAsync(int emoteId);
    ValueTask ChangeSceneAsync(int sceneId, float x, float y);
    ValueTask LeaveAsync();
}
```

## 5. ProjectF.HubServer

Kestrel HTTP/2 cleartext on localhost:5170. `PlayerHub : StreamingHubBase<...>` grouping by
`scene-{sceneId}`, backed by a singleton `PresenceRegistry` (ConcurrentDictionary per scene).
`ChangeSceneAsync` must leave the old group and join the new one.
`OnDisconnected` MUST remove the player and broadcast `OnLeave` — no ghost players.

## 6. ProjectF.SeedNode

Headless node: `appsettings.json` with StorePath, GenesisPath, Host, Port, PrivateKeyHex,
IsMiner, TargetBlockIntervalMs (2000), StaticPeers[].
On startup print the node address AND a copy-pasteable **peer string**
(`{publicKeyHex},{host},{port}`) — this is what the Unity client pastes into its settings.
Graceful Ctrl+C shutdown. Mining loop honours the target block interval.

## 7. Unity client

`RootLifetimeScope` registers as singletons: `TableService`, `KeyStore`, `LibplanetClient`
(as `ILibplanetClient`), `ActionQueue`, `StateWatcher`, `PlayerHubClient` (as `IPresenceClient`),
`SceneRouter`; entry point `AppBootstrapper : IAsyncStartable` running:
load tables → load/create key → start embedded node & sync → connect presence (fire-and-forget,
MUST NOT block gameplay if the hub is down) → route to Village scene.

- `ActionQueue.SubmitAsync(action, ct)` → stage tx, raise `OnStaged`, await confirmation
  with a 30s timeout, raise `OnConfirmed`/`OnFailed`. Never throw into the caller; return bool.
- `StateWatcher` polls avatar/inventory/pond state on new tip and raises typed events.
- `PlayerHubClient` throttles `SendMove` to 10 Hz, but sends immediately when Direction or
  AnimationState changes. Catches connection failure and degrades to offline mode with a warning.
- `FishingPresenter` orchestrates: `OccupyPondAction` → client mini-game (cosmetic only) →
  `FishingAction` → diff inventory before/after to decide which catch animation to play.
- Generate the matching `FishingView`, `HudView/HudPresenter`, `RemotePlayerRegistry`,
  `RemotePlayerFactory` (with position interpolation), and one `LifetimeScope` per scene.
- `NetworkSettings` ScriptableObject: SeedPeers[], HubHost, HubPort, NodePort (0 = random),
  StorePath template containing `{instanceId}` — required so two builds on one machine
  don't lock the same chain store.
